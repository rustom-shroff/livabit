## User experience

1. Configure the explicitly selected existing OpenClaw agent or start the independent display receiver. Transfer a USB, emulator or private Wi-Fi setup into **liveabit Sender**. File import fills the draft without starting sharing or replacing saved state. Both formats contain `url`, `key` and optional integer `warning_minutes` (default 60), capped at 8 KiB. The display receiver uses `liveabit.receiver.connection.v1` and exact `/events`. OpenClaw uses `liveabit.openclaw.connection.v1` with required `agent_id` matching `[a-z0-9][a-z0-9_-]{0,63}`. Exact `/hooks/liveabit` requires `liveabit`, matching the server-owned dedicated route. For compatibility, import an older main-agent export for this exact mapped path by visibly changing only the draft agent to liveabit; keep its address and key. Generic `/hooks/agent` retains its configured allowed agent, including main. The manual editor contains address/key/agent fields only, with liveabit the new manual default; the agent is effective only for OpenClaw paths. Reject invalid formats/endpoints/agent IDs/keys/intervals before changing fields, and show a safe precise error inline and in a dialog. Identify host-format `connection.json` as a computer file and name `android-wifi-setup.json` or `android-usb-setup.json` as the usable phone files. Never show raw parser text or file contents.
2. Choose up to 32 apps, grant Android usage access separately, and optionally enable receiver-warning notifications. Explain that Start shares the selected apps' last 15 minutes and onward. No content, messages, class names or browsing activity is read.
3. Start sharing. Read only the chosen packages' lifecycle fields through `UsageEventsQuery`, validate the bounded read with the accepted native core and estimate the new window in the publisher. Read only screen-off timestamps separately for local interval boundaries. Carry private open-session context across adjacent windows in the same boot; discard it on gaps, clock discontinuity, age, collection failure, permission loss or Stop. Commit context only with a successfully advanced cursor. Empty observations mean unknown usage. A selected-app estimate can be null; coverage stays unknown.
4. Display connection state, configured destination/profile and OpenClaw agent, pending event count, last acceptance and warning interval. Wi-Fi/USB instructions use the actual endpoint/port. Provide Send now and Stop sharing on Activity, with connection editing in Setup. Identify new-endpoint acknowledgement as durable receipt and legacy-hook acknowledgement as run admission; neither establishes finished reasoning or a phone nudge. Repeating Start with the same endpoint, effective agent, key and apps preserves session/cursor/queue/outage timer; warning changes preserve them too. Changing endpoint, agent, key or apps requires explicit Start and confirmation before discarding unexpired pending activity. Cancel keeps saved setup. Preserve original meaningful pending wrappers and legacy import behavior.
5. Schedule persisted one-off Android jobs at the configured active interval (default five minutes). Check local screen interactivity and pause all automatic network requests after the configurable screen-off cutoff (default fifteen minutes). Recover screen history when the process missed its broadcast. Recheck locally while paused and resume the active schedule on screen-on/reopen. For both automatic and manual OpenClaw sends, require a positive numeric selected-app foreground duration; transition counts alone and null/zero durations are insufficient. Skip empty scans without creating an event, advancing its sequence or starting an outage, while advancing the successful local cursor/context. Prune known empty OpenClaw queued wrappers without rewriting meaningful pending bytes; if this empties the queue, clear its false failure/alert state. Keep eligible meaningful retries and prune expired items. Manual empty display-receiver diagnostics may still be sent without model use. Alternate job slots, binding each to the sharing stream and schedule revision. Retain at most 64 pending events for at most 24 hours in private atomic storage. Retry unchanged request bytes and event identity; never relabel a retry as a fresh event. The test receiver deduplicates saved events. OpenClaw has only a bounded in-memory idempotency cache, so retries may produce duplicates after expiry or restart. One wake sends at most four pending pages.
6. Changing the active interval, screen-off cutoff or warning interval must preserve the sharing stream, cursor, pending bytes and existing outage timer. Settings save is atomic and rejects invalid values without partial changes. Older saved state gains 5/15 defaults without rewriting its queue. Start the outage timer at the first unsuccessful acknowledgement. Subsequent failures do not reset it. Default warning interval is 60 minutes; the user can save a value from 1 through 1440 minutes without resetting the connection. Use elapsed time within the same boot and persisted time across reboot. Notify once per outage with **Receiver is down**, explaining that missing acknowledgements may mean a receiver or connection problem. Correct recovery cancels the warning and resets the timer. No warning after sharing is stopped.
7. Persist the user's sharing on/off choice independently of the Activity/process lifetime. On normal boot after first unlock, app update or reopening, restore an enabled sender's missing one-off jobs or replace its old periodic job without resetting stream, pending bytes, cursor or failure timer. A stopped sender remains stopped and has no sending/outage jobs. Keep daily Start/Send/Stop/status in Activity and remove Change apps or connection. Setup exposes exactly three connection choices: Import receiver file, Connect to OpenClaw and Edit connection manually. Expanding the manual editor, opening the keyboard and recreating Activity must retain these same three actions; no nested paste/Wi-Fi/USB buttons appear. Manual fields remain expanded after recreation. The no-config OpenClaw dialog offers Import receiver file, Edit connection manually and Close. Apps to share and sharing controls remain. Settings holds timing/warnings. A force-stopped app cannot run until reopened. Distinguish unreachable receiver, refused connection key, HTTP rejection/unavailability and invalid acknowledgement in status. Warning status checks permission, app notifications and the warning channel together; provide the relevant Android settings when disabled.

## Connection-file import

Show Importing connection immediately. Read at most 8 KiB on a dedicated file-import thread, independently of the serial delivery worker, so a timed-out send cannot delay local file feedback. Guard results against newer imports, draft edits and destroyed/recreated Activities. Disable import/connect while an import is active. Successful parsing updates draft fields only; enabled state, selected apps, saved destination/key/agent, settings, stream, sequence, cursor, outage timestamps and meaningful pending request bytes stay unchanged. The existing Start/confirmation flow applies a changed draft. Invalid input preserves both draft and saved state.

Show controlled validation messages in Setup and a Could not import connection dialog. Distinguish malformed JSON, oversized files, wrong host configuration, missing/invalid fields and address/profile/agent mismatch without exposing keys or raw JSON. Retained main-agent `/hooks/liveabit` exports show Older OpenClaw setup updated to liveabit and invite the user to check the draft. This migration does not change generic `/hooks/agent` main exports, retarget pending bytes or alter OpenClaw configuration.

## Remembered sharing and startup restoration

Use the existing private persisted enabled state as the user's choice. Closing the Activity, process recreation, phone shutdown and installing an update must not replace it with a runtime-service flag. Stop sharing persists disabled state and cancels both automatic delivery and outage jobs; boot or update must never change disabled to enabled.

A non-exported native StartupReceiver handles `BOOT_COMPLETED` and `MY_PACKAGE_REPLACED` and calls the same idempotent scheduling restoration used on reopening. It performs local scheduling only: it does not create an OAP observation, send an HTTP request, launch UI or start a foreground service in the broadcast callback. Scheduling can read local screen history to respect the existing idle pause. Existing persisted JobScheduler jobs normally survive reboot; restoration also recreates them if missing and keeps their stream/revision binding. Repeated restoration must not create duplicate jobs or reset the sharing session. No new runtime dependency or intermediary is introduced.

Connection credentials and saved setup remain in credential-protected private storage. Normal monitoring resumes after the first unlock following startup, rather than during locked direct boot. Retain selected apps, receiver/agent/key, active/screen-off/warning settings, immutable meaningful pending requests, sequence, stream and outage timestamps. The existing collector bounds a new read to the current boot/uptime and rejects continuity context from an earlier boot; a powered-off interval must not become inferred foreground use. Existing expiry, positive-duration gate, screen-off pause and best-effort timing still apply. Restore does not mean an immediate network request or bypass notification permission.

Android Force stop is an explicit OS block on background execution until the user opens the app again. Reopening restores the saved enabled state; a stopped state stays stopped. Installing 0.11.0 over the existing sender retains setup and state, including an already-correct liveabit Wi-Fi connection; uninstalling or clearing storage removes them.

## Immediate OpenClaw connection check

Connect to OpenClaw checks the current draft without starting sharing or modifying saved stream, queue, cursor or outage state. Run the bounded check on a dedicated background thread so ongoing delivery cannot block feedback. Protect against stale results after edits, a newer check or Activity destruction. Disable redirects, use five-second connect/read limits and POST authenticated `{}` without an OAP message or idempotency key.

Accept only HTTP 400 with literal `ok: false` and the installed handler's exact error: `hook mapping requires message` for `/hooks/liveabit`, or `message required` for `/hooks/agent`. Authentication is checked before message validation; the missing-message response therefore confirms reachable address, accepted key and recognized handler. It does not prove agent allowlist, model execution or interpretation. Reject unexpected 200/400 bodies and redirects. Show progress/result persistently in Setup and failures in an error dialog, distinguishing refused keys, missing routes, server errors and unreachable/timeout states without exposing secrets. If no OpenClaw draft exists, offer Import receiver file, Edit connection manually and Close; import there also checks the OpenClaw draft. Top-level Import receiver file only fills the draft.

For `/liveabit/activity`, require HTTP 400, literal `ok:false`, exact `error:activity_message_required` **and** `format:liveabit.activity-receipt.v1`. This confirms the authenticated plugin route without submitting activity or admitting model work. A generic 400 or malformed/other-version marker must fail. New-endpoint import accepts an explicitly valid configured agent ID without rewriting it to dedicated liveabit; only legacy exact-hook imports retain their visible main-to-liveabit draft migration. The server's trusted mapping, not the wrapper's agent text, owns routing.

## Observation record

The sender produces the [OAP observation draft 2](../protocol/activity-observation-draft-2.md), `protocol_version: 0.2.0-draft.2`, `event_name: activity.observation`. It carries immutable event/window identities, durable local recipient/subscription/stream identities, a sequence and restricted UTC millisecond timestamps. Selected apps live under `observation.apps`, with nullable durations and projected transition counts; coverage stays unknown and quality is an unverified estimate. Canonical event bytes are capped at 16 KiB, and expiry is derived from window start plus at most 24 hours. No raw lifecycle trace or personal agent context is sent. New windows cover at most 15 minutes; missed older history is not silently presented as complete. The existing OAP 0.1.0 measured-summary contract remains unchanged.

## Independent test receiver transport

POST UTF-8 JSON to the exact configured `/events` URL with a bearer connection key. Disable redirects. Accept only HTTP 200 with `accepted: true`, `receiver: liveabit-test-receiver`, matching `event_id` and SHA-256 of the exact submitted bytes. This acknowledges only the final test receiver's saved event, never agent interpretation. Keep the pending page on transport failure, rejection, malformed response or an incorrect identity/digest.

The receiver validates the actual OAP schema, canonical bytes, app ordering, timestamp chronology and measurement bounds; it expires stale events, saves accepted bytes' digest plus display data before acknowledging, and displays the latest 200 events. A repeated ID with matching digest is acknowledged as a duplicate; a changed body under an existing ID is rejected. It also accepts unchanged OAP draft-1 observations with their original semantic validation, and already queued `liveabit.test.activity.v1` events unchanged from older APKs. Native storage migration adds missing local identities while keeping old pending bytes and session state. Dashboard modes can withhold acknowledgements or return an incorrect acknowledgement while still displaying an event. These modes test Android behavior directly. No forwarding, coaching or agent invocation exists.

## Direct OpenClaw transport

The current personal-agent runtime supports two separate acknowledgement contracts. Endpoint choice is explicit in saved setup; do not fall back from one endpoint/channel to another after failure. Both retain direct phone-to-chosen-gateway topology, the separate activity hook bearer token, original canonical OAP bytes inside the fixed data wrapper, `deliver:false`, no caller-selected session and original event identity on retry. New `/liveabit/activity` setup uses the same `liveabit.openclaw.connection.v1` file format with its explicit new URL; old APKs must not be given it as if they already supported durable receipts.

### Durable receipt endpoint

POST to exact `/liveabit/activity`. Accept only HTTP 200 with literal `ok:true`, `durable:true`, exact `format:liveabit.activity-receipt.v1`, matching `event_id` and SHA-256 of the exact submitted wrapper bytes. Valid disposition is `accepted`, `empty` or `expired`; `duplicate` must also identify one of those as `original_admission`. A fabricated/legacy `runId` cannot replace these fields. A terminal empty/expired disposition allows removing those bytes from the sender queue but does not schedule an intervention. The optional processing facts in the acknowledgement do not prove model completion or notification.

The receiver commits retained evidence and a qualifying analysis obligation together before acknowledging. It creates no immediate model run; the host worker coalesces and recovers review independently. Identical replay contributes no extra usage or review generation. Conflicting identity/body fails safely. The phone keeps meaningful pending bytes on failed, mismatched or malformed acknowledgement and retains existing expiry/consent/backoff/outage rules. The host's durable deduplication and finite retention remain distinct from the legacy native idempotency cache.

### Legacy hook compatibility

POST only to the exact configured `/hooks/liveabit` or `/hooks/agent` with the separate hook token; disable redirects. Android's legacy mapped route retains its saved liveabit wrapper/import compatibility, while current trusted host settings route it to the same main personal agent's isolated activity session. The legacy built-in route uses an explicitly allowed saved agent. Use `name:liveabit`, `wakeMode:now`, `deliver:false` and no caller session key. Persist the fixed data introduction/original canonical OAP wrapper once and retry unchanged bytes with original event ID as `Idempotency-Key`. Legacy hook use still requests per-packet analysis, not the durable worker path.

A versioned native OpenClaw hook transform returns null for known empty, expired or invalid observation wrappers, producing HTTP 204 without agent/model dispatch. It preserves meaningful original messages and leaves empty `{}` connection checks to the installed missing-message handler. This is part of the final agent infrastructure, not a relay. HTTP 204 is a drop, not Android run admission; current Android avoids empty requests locally.

Accept only HTTP 200 containing literal `ok: true` and a valid nonempty string `runId`. Report run admission, remove that admitted pending event and reset the outage timer. It does not prove interpretation, notification or an OAP valid-consumption receipt. Keep meaningful events pending on transport failure, refusal or malformed acknowledgement. The installed 2026.9.9 implementation caches idempotency in memory for five minutes; response loss and later retry/restart can produce another run. Preserve original identity and time for agent duplicate recognition.

Current host setup follows [the personal-agent runtime](../../integrations/openclaw/personal-agent/README.md), preserving main's identity/model, authorized context and shared Workboard while isolating activity from ordinary chat. Tasks are one possible source of a useful alternative, not a prerequisite for support. The sender receives no goals, feelings, private memory or task details. OAP is untrusted evidence and authorizes no task mutation, worker dispatch, Goal creation, external message or device restriction.

Main manages actual user tasks in canonical Workboard. An activity session can read relevant open cards across agents through available authorized host tools; it must not create a shadow list or reinterpret execution `scheduledAt` as a completion deadline. Ordinary main chat may retrieve bounded activity evidence and deliberately record a linked report for reconsideration. Neither shared identity nor an installed Skill proves access to all past conversations. Physical companion replies and useful adaptation require separate evaluation.

Intervention delivery uses only the [current private companion route](../../docs/integration-drafts/openclaw-companion-notifications.md), with stored decision text, runtime preferences/freshness and a durable native-attempt guard. Questions invite the existing companion chat; native acknowledgement is not display, reading or a useful conversation. Known pre-invocation disconnection can wait within limits; uncertain invocation cannot be blindly retried. Automatic accountability emails and alternate-channel fallback remain disabled. The sender's receiver-outage warning remains distinct from an agent intervention.

Earlier dedicated-agent task-only and WhatsApp instructions remain historical in the [dated direct integration guide](../../docs/integration-drafts/openclaw-direct.md) and release reviews. They must not overwrite a current personal-agent configuration. Current setup preserves user-owned model/reasoning settings and generates private files using the actual approved endpoint/port. No firewall/router change or physical phone installation follows merely from building the candidate. Earlier physical admission was user-confirmed without an independently read APK hash/version; it cannot prove the new receipt contract.

## Shared local transport and storage limits

The key is encrypted using Android Keystore and held only in the app's private no-backup settings. Pending activity is private and excluded from cloud backup/device transfer. HTTP is limited to localhost/private IPv4 destinations for this local POC; HTTPS is also accepted. Local HTTP is not a production transport-security claim. The desktop test receiver defaults to loopback; LAN listening is a user-selected option. OpenClaw retains its configured binding unless the user selects a change. Connection files, credentials and received data stay in ignored local artifacts.

## Setup regression release gate

The 0.10.0 failures came from missing compatibility and incorrect test expectations. The dedicated-route agent change rejected previously exported main-agent files without import migration, and a generic error hid that cause. The three-option UI test inspected collapsed direct children, while other tests explicitly expected extra paste/Wi-Fi/USB actions inside manual editing. Picker tests used display-receiver files; OpenClaw tests passed setup directly to the delivery engine, bypassing file parsing and picker behavior. Those passes did not prove the user's setup workflow.

For every changed sender APK, run `SetupRegressionCases` through the normal native harness before recommending a phone trial. `setup_regression_ui` recursively checks exactly three visible connection actions when collapsed, expanded, with the keyboard actually visible and after Activity recreation; it also checks the no-config dialog. `setup_import_regression` opens Android's actual document picker for current and retained OpenClaw exports, the wrong host `connection.json`, malformed secret-bearing JSON and a receiver export. It verifies precise secret-free inline/dialog failures, retained drafts on errors, imports independent of a blocked sending worker and unchanged saved enabled/apps/connection/settings/session/sequence/cursor/pending/outage state. In `-OpenClaw` mode, use copies of the actual generated current Wi-Fi export and retained pre-migration export; synthetic fallback exports in offline mode are a distinct scope. Private exports stay outside Git.

For this fix, run the same new UI and retained-file picker tests against the retained 0.10.0 APK first and record failures at the reported behaviors. Then run the full harness on the exact 0.11.0 candidate and record its hash, environment and results. Future changes must keep these checks in the standard harness; require a regression test to fail against the affected earlier build when reproducing a newly reported setup defect. Direct engine admission, parser-only tests and a collapsed screen check cannot substitute for these workflows. Frozen earlier reviews remain unchanged.
