# Android sender: direct OpenClaw and final test receiver

Revision **0.5, 2026-10-11**. Native development is authorized by [ADR-0015](../../docs/decisions/0015-android-first-test-receiver.md); [ADR-0017](../../docs/decisions/0017-openclaw-direct-integration.md) selects the installed OpenClaw runtime as the direct agent target. The sender supports that native webhook and the independent desktop display receiver, without a forwarding bridge. Implement and test behavior in Android, not a JavaScript sender prototype. Exact 0.4.0 APK bytes passed 31 native emulator checks and actual OpenClaw admission; separate agent history verified uncertainty-preserving interpretation. The [POC review](../../docs/review/openclaw-poc-2026-10-11.md) records scope and limits.

## User experience

1. Configure the dedicated OpenClaw activity agent or start the independent desktop display receiver. Transfer a setup for USB, emulator or private Wi-Fi into **liveabit Sender**. Native file import and explicit clipboard paste fill the address, key and warning interval together; importing never starts sharing or replaces the saved session. Manual fields remain available. Both setup formats contain `url`, `key` and optional integer `warning_minutes` (default 60), capped at 8 KiB. The display receiver uses `format: liveabit.receiver.connection.v1`; OpenClaw uses `format: liveabit.openclaw.connection.v1` and fixed `agent_id: liveabit`. Require the format to match `/events` or `/hooks/agent` respectively. Reject unsupported formats, invalid endpoints, keys and intervals before changing fields. Read the clipboard only in response to the Paste button.
2. Choose up to 32 apps, grant Android usage access separately, and optionally enable receiver-warning notifications. Explain that Start shares the selected apps' last 15 minutes and onward. No content, messages, class names or browsing activity is read.
3. Start sharing. Read only the chosen packages through `UsageEventsQuery`, reuse the accepted native estimator and send aggregated usage estimates. Empty observations mean unknown usage. A selected-app estimate can be null; coverage stays unknown.
4. Display connection state, configured destination/profile, pending event count, last acknowledgement and configured warning interval. Provide native OpenClaw, Wi-Fi and USB guides, Send now and Stop sharing. Identify OpenClaw acknowledgement as run admission. Repeating Start with the same receiver, key and selected apps keeps the session, cursor, pending events and outage timer; warning-interval changes preserve them too. Changing receiver, key or selected apps requires explicit Start, with confirmation before discarding unexpired pending events from the previous setup. Cancel retains the saved setup and its pending activity.
5. Schedule background collection/delivery approximately every 15 minutes using Android JobScheduler. Retain at most 64 pending events for at most 24 hours in private atomic storage. Retry unchanged request bytes and event identity; never relabel a retry as a fresh event. The test receiver deduplicates saved events. OpenClaw has only a bounded in-memory idempotency cache, so retries may produce duplicates after expiry or restart. One wake sends at most four pending pages.
6. Start the outage timer at the first unsuccessful acknowledgement. Subsequent failures do not reset it. Default warning interval is 60 minutes; the user can save a value from 1 through 1440 minutes without resetting the connection. Use elapsed time within the same boot and persisted time across reboot. Notify once per outage with **Receiver is down**, explaining that missing acknowledgements may mean a receiver or connection problem. Correct recovery cancels the warning and resets the timer. No warning after sharing is stopped.
7. Reopening an enabled sender restores any missing background delivery job and outage check without resetting its stream, pending bytes, cursor or failure timer. A force-stopped app cannot run until reopened. Distinguish unreachable receiver, refused connection key, HTTP rejection/unavailability and invalid acknowledgement in status. Warning status checks permission, app notifications and the warning channel together; provide the relevant Android settings when disabled.

## Observation record

Sender 0.4.0 retains the [OAP observation draft](../protocol/activity-observation.md), `protocol_version: 0.2.0-draft.1`, `event_name: activity.observation`. It carries immutable event/window identities, durable local recipient/subscription/stream identities, a sequence and restricted UTC millisecond timestamps. Selected apps live under `observation.apps`, with nullable durations and projected transition counts; coverage stays unknown and quality is an unverified estimate. Canonical event bytes are capped at 16 KiB, and expiry is derived from window start plus at most 24 hours. No raw lifecycle trace or personal agent context is sent. New windows cover at most 15 minutes; missed older history is not silently presented as complete. The existing OAP 0.1.0 measured-summary contract remains unchanged.

## Independent test receiver transport

POST UTF-8 JSON to the exact configured `/events` URL with a bearer connection key. Disable redirects. Accept only HTTP 200 with `accepted: true`, `receiver: liveabit-test-receiver`, matching `event_id` and SHA-256 of the exact submitted bytes. This acknowledges only the final test receiver's saved event, never agent interpretation. Keep the pending page on transport failure, rejection, malformed response or an incorrect identity/digest.

The receiver validates the actual OAP schema, canonical bytes, app ordering, timestamp chronology and measurement bounds; it expires stale events, saves accepted bytes' digest plus display data before acknowledging, and displays the latest 200 events. A repeated ID with matching digest is acknowledged as a duplicate; a changed body under an existing ID is rejected. It also accepts already queued `liveabit.test.activity.v1` events unchanged from older APKs. Native storage migration adds missing local identities while keeping old pending bytes and session state. Dashboard modes can withhold acknowledgements or return an incorrect acknowledgement while still displaying an event. These modes test Android behavior directly. No forwarding, coaching or agent invocation exists.

## Direct OpenClaw transport

POST to the exact configured `/hooks/agent` URL with the dedicated hook bearer token, distinct from the gateway administration token. Disable redirects and fix `agentId` to `liveabit`, `name` to `liveabit`, `wakeMode` to `now` and `deliver` to `false`. The `message` contains a fixed activity-data introduction followed by the original canonical observation JSON. Construct and persist the complete provider request once, then retry those unchanged bytes. Set `Idempotency-Key` to the original observation's `event_id`.

Accept only HTTP 200 containing literal `ok: true` and a valid nonempty string `runId`. Show this as run admission, remove that admitted pending event and reset the outage timer. It does not prove interpretation, notification or an OAP valid-consumption receipt. Keep events pending on transport failure, refusal or malformed acknowledgement. The verified OpenClaw 2026.9.9 implementation caches idempotency in memory for five minutes; response loss followed by retry after cache expiry or restart can produce another run. Preserve identity and original time so the agent can recognize duplicates.

Configure a dedicated workspace with liveabit Skill guidance and the existing model configuration. Deny the ordinary host tool catalog and disable hook channel delivery and heartbeat. OpenClaw CodeMode still exposes JavaScript `exec`/`wait` and `skills.read`; the observed run read the Skill. Do not describe this as zero tools or no execution. Activity content remains untrusted data and cannot authorize device actions. Inspect actual agent output separately from delivery acknowledgement.

The [local setup helper](../../scripts/configure-openclaw.ps1) preserves unrelated configuration and produces private USB/emulator setup files. Without `-Lan`, it leaves the existing gateway binding unchanged. The user-approved `-Lan` setup additionally enables direct local-network access and creates Wi-Fi files. Derive addresses and the actual port from generated setup; do not assume a default port or introduce a relay. Emulator-to-host-LAN admission has been verified; physical-phone Wi-Fi delivery remains untested.

## Shared local transport and storage limits

The key is encrypted using Android Keystore and held only in the app's private no-backup settings. Pending activity is private and excluded from cloud backup/device transfer. HTTP is limited to localhost/private IPv4 destinations for this local POC; HTTPS is also accepted. Local HTTP is not a production transport-security claim. The desktop test receiver defaults to loopback; LAN listening is a user-selected option. OpenClaw retains its configured binding unless the user selects a change. Connection files, credentials and received data stay in ignored local artifacts.

## Native verification and limits

Test the actual APK on the owned emulator against the actual receiver: source selection, observed lifecycle transitions, matching acknowledgement, incorrect acknowledgement refusal, persisted pending bytes, deduplicated retry, real notification after a one-minute user setting, recovery, stop, JobScheduler dispatch and rendered connection screen. Also exercise real receiver setup parsing, clipboard paste, the Android document picker, bad-key/unreachable responses, permission-disabled warning status and force-stop/reopen with retained event bytes and restored jobs. Exercise rendered Wi-Fi/USB guides, connection descriptions, same-setup Start preserving the queue/timer, and both Cancel and Confirm in the changed-setup dialog. The harness owns an isolated copy of the actual receiver on an ephemeral port under its unique test-run directory, closes it in cleanup and never uses the user's main receiver or files. Dispatch native test delivery on the same serial app worker used by the UI and JobService. Check the default one-hour configuration without adding a one-hour wait to routine development. Bind the installed APK hash to the candidate before recommending phone testing.

Also exercise native OpenClaw setup/destination constraints, actual collector-to-hook request construction/authentication/idempotency, strict acknowledgement refusal, durable retry and recovery. The `-OpenClaw` test mode delivers an owned emulator observation directly to the installed gateway. Record its run admission separately from actual agent history. Exact 0.4.0 APK SHA-256 `43650faaef9f304a2a2f4d7522f43be6a78255df77bfc242c2b70623b5e78273` passed [31 checks on Android 15/API 35](../../artifacts/android-publisher/run-ea7f57fe-4d14-4b9d-aed9-c6d1828b16c3/validation.json). Separate native [emulator-to-host-LAN admission](../../artifacts/openclaw/android-lan-admission.json) passed through the generated Wi-Fi setup. The observed agent retained unknown coverage and unverified duration and did not infer leaving the app from transition count.

Android can delay JobScheduler work under Doze, battery restriction or other OS conditions. A threshold is not an exact alarm guarantee; force-stopping the app prevents background work until reopened. Notification permission or a disabled channel prevents visible alerts. Tests do not prove physical-phone delivery/timing, source completeness, battery use or production OAP conformance. The observed agent output is one event's result, not general interpretation quality or completed production M2/M3.
