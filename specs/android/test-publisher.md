## User experience

1. Configure the explicitly selected existing OpenClaw agent or start the independent display receiver. Transfer a USB, emulator or private Wi-Fi setup into **liveabit Sender**. File import and explicit clipboard paste fill fields without starting sharing or replacing the saved session. Both formats contain `url`, `key` and optional integer `warning_minutes` (default 60), capped at 8 KiB. The display receiver uses `liveabit.receiver.connection.v1` and exact `/events`. OpenClaw uses `liveabit.openclaw.connection.v1` with required `agent_id` matching `[a-z0-9][a-z0-9_-]{0,63}`. Exact `/hooks/liveabit` requires `main`, matching the server-owned route; legacy `/hooks/agent` permits a configured agent, including `liveabit`. Provide an editable OpenClaw agent field, filled by import and defaulting to main for new manual setup; it is effective only for OpenClaw paths. Reject invalid formats/endpoints/agent IDs/keys/intervals before changing fields. Read the clipboard only after Paste.
2. Choose up to 32 apps, grant Android usage access separately, and optionally enable receiver-warning notifications. Explain that Start shares the selected apps' last 15 minutes and onward. No content, messages, class names or browsing activity is read.
3. Start sharing. Read only the chosen packages through `UsageEventsQuery`, reuse the accepted native estimator and send aggregated usage estimates. Empty observations mean unknown usage. A selected-app estimate can be null; coverage stays unknown.
4. Display connection state, configured destination/profile and OpenClaw agent, pending event count, last acknowledgement and warning interval. Native Wi-Fi/USB guides follow the entered/imported OpenClaw endpoint and actual port rather than showing `/events` receiver launch instructions. Provide OpenClaw help, Send now and Stop sharing. Identify acknowledgement as run admission. Repeating Start with the same endpoint, effective agent, key and apps preserves session/cursor/queue/outage timer; warning changes preserve them too. Changing endpoint, agent, key or apps requires explicit Start and confirmation before discarding unexpired pending activity. Cancel keeps the saved setup. Migrate older fixed-agent settings to liveabit and preserve original pending wrappers.
5. Schedule background collection/delivery approximately every 15 minutes using Android JobScheduler. Retain at most 64 pending events for at most 24 hours in private atomic storage. Retry unchanged request bytes and event identity; never relabel a retry as a fresh event. The test receiver deduplicates saved events. OpenClaw has only a bounded in-memory idempotency cache, so retries may produce duplicates after expiry or restart. One wake sends at most four pending pages.
6. Start the outage timer at the first unsuccessful acknowledgement. Subsequent failures do not reset it. Default warning interval is 60 minutes; the user can save a value from 1 through 1440 minutes without resetting the connection. Use elapsed time within the same boot and persisted time across reboot. Notify once per outage with **Receiver is down**, explaining that missing acknowledgements may mean a receiver or connection problem. Correct recovery cancels the warning and resets the timer. No warning after sharing is stopped.
7. Reopening an enabled sender restores any missing background delivery job and outage check without resetting its stream, pending bytes, cursor or failure timer. A force-stopped app cannot run until reopened. Distinguish unreachable receiver, refused connection key, HTTP rejection/unavailability and invalid acknowledgement in status. Warning status checks permission, app notifications and the warning channel together; provide the relevant Android settings when disabled.

## Observation record

The sender retains the [OAP observation draft](../protocol/activity-observation.md), `protocol_version: 0.2.0-draft.1`, `event_name: activity.observation`. It carries immutable event/window identities, durable local recipient/subscription/stream identities, a sequence and restricted UTC millisecond timestamps. Selected apps live under `observation.apps`, with nullable durations and projected transition counts; coverage stays unknown and quality is an unverified estimate. Canonical event bytes are capped at 16 KiB, and expiry is derived from window start plus at most 24 hours. No raw lifecycle trace or personal agent context is sent. New windows cover at most 15 minutes; missed older history is not silently presented as complete. The existing OAP 0.1.0 measured-summary contract remains unchanged.

## Independent test receiver transport

POST UTF-8 JSON to the exact configured `/events` URL with a bearer connection key. Disable redirects. Accept only HTTP 200 with `accepted: true`, `receiver: liveabit-test-receiver`, matching `event_id` and SHA-256 of the exact submitted bytes. This acknowledges only the final test receiver's saved event, never agent interpretation. Keep the pending page on transport failure, rejection, malformed response or an incorrect identity/digest.

The receiver validates the actual OAP schema, canonical bytes, app ordering, timestamp chronology and measurement bounds; it expires stale events, saves accepted bytes' digest plus display data before acknowledging, and displays the latest 200 events. A repeated ID with matching digest is acknowledged as a duplicate; a changed body under an existing ID is rejected. It also accepts already queued `liveabit.test.activity.v1` events unchanged from older APKs. Native storage migration adds missing local identities while keeping old pending bytes and session state. Dashboard modes can withhold acknowledgements or return an incorrect acknowledgement while still displaying an event. These modes test Android behavior directly. No forwarding, coaching or agent invocation exists.

## Direct OpenClaw transport

POST only to the exact configured `/hooks/liveabit` or `/hooks/agent` URL with the hook bearer token, distinct from gateway administration authentication. Disable redirects. The built-in route uses the saved agent ID; the mapped liveabit route requires main and fixes both agent and conversation in native server configuration. Use `name: liveabit`, `wakeMode: now` and `deliver: false`; no client-provided session key. The `message` contains a fixed activity-data introduction followed by the original canonical JSON. Persist the complete provider request once and retry unchanged bytes. Set `Idempotency-Key` to the original observation's event ID.

For new 0.6.0 requests, the fixed introduction says ordinary replies stay local and only separate explicit host delivery policy may authorize a selective nudge. It supplies no goal, target or model choice. Existing pending requests retain their original bytes. OpenClaw's own private policy fixes the linked WhatsApp self target, defaults to editable 60-minute cooldown and 22:00–08:00 America/Chicago quiet hours, and requires established goals/context before an unsolicited nudge. These are best-effort agent instructions, with incoming direct/group chats disabled. Activity and channel helpers preserve the user's model/thinking choice; Android stores neither it nor private agent context.

Accept only HTTP 200 containing literal `ok: true` and a valid nonempty string `runId`. Show this as run admission, remove that admitted pending event and reset the outage timer. It does not prove interpretation, notification or an OAP valid-consumption receipt. Keep events pending on transport failure, refusal or malformed acknowledgement. The verified OpenClaw 2026.9.9 implementation caches idempotency in memory for five minutes; response loss followed by retry after cache expiry or restart can produce another run. Preserve identity and original time so the agent can recognize duplicates.

For main, install liveabit Skill in its existing workspace, adding it to an explicit skill allowlist when needed. Preserve AGENTS, model, tools, heartbeat, other skills and unrelated configuration. The native `/hooks/liveabit` mapping uses `action: agent`, fixed main agent ID and canonical main session key, `sessionMode: persistent`, `messageTemplate: {{message}}`, immediate wake and no hook channel delivery. Keep caller session selection disabled. This is part of OpenClaw, not a forwarding service. The first hook created the configured canonical conversation because no record existed before setup; earlier chats were not imported. Context stays in the host; neither Android nor setup reads/copies goals or chats. Runtime continuity, context use and channel notification are separate evidence.

The older dedicated liveabit agent and `/hooks/agent` isolated-run setup remain supported. Its ordinary host catalog denial and disabled heartbeat do not apply to main. OpenClaw CodeMode exposes JavaScript `exec`/`wait` and `skills.read`; do not claim zero tools or no execution. Activity remains untrusted data and cannot authorize device actions or change routing. Inspect actual output separately from admission.

The [helper](../../scripts/configure-openclaw.ps1) defaults to selected agent main, merges hook/skill allowlists without replacing prior entries and produces private USB/emulator files. Without `-Lan`, it preserves the gateway binding; the user-approved LAN option creates Wi-Fi files. Derive actual addresses/port from setup. Native [main-agent emulator-to-host-LAN admission](../../artifacts/openclaw/android-main-lan-admission.json) passed using the exact 0.5.0 APK; dedicated-agent 0.4.0 LAN evidence remains separate. Physical-phone Wi-Fi remains untested. Main's configuration entry and AGENTS were unchanged after setup.

## Shared local transport and storage limits

The key is encrypted using Android Keystore and held only in the app's private no-backup settings. Pending activity is private and excluded from cloud backup/device transfer. HTTP is limited to localhost/private IPv4 destinations for this local POC; HTTPS is also accepted. Local HTTP is not a production transport-security claim. The desktop test receiver defaults to loopback; LAN listening is a user-selected option. OpenClaw retains its configured binding unless the user selects a change. Connection files, credentials and received data stay in ignored local artifacts.
