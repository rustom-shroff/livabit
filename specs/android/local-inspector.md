# Android local collector and inspection prototype

Revision: 0.6, 2026-10-07. Authorized by [ADR-0009](../../docs/decisions/0009-android-local-inspection-first.md), the user's instruction to continue after [their qualitative phone trial](../../docs/review/android-phone-feedback-2026-10-05.md), their requirement to validate delivered APKs in an emulator before another phone trial, and their authorization to continue autonomously. Task: TASK-P6-F02. This is a local measurement app, not an OAP publisher or evidence of M2/M3 completion.

## User flow

1. Add one or more apps using a system picker where available, or enter an exact package identifier. Show the resulting selected identities. Never request all-package visibility or enumerate an app inventory.
2. Explain that Android usage access is broad OS permission while this app reads only selected packages. Open usage-access Settings on request and recheck AppOps; returning from Settings is not approval. Refresh the visible permission status when Android notifies of a change, including while the local session is stopped. A regrant does not start a session or restore cleared observations. Device must be unlocked. Only MODE_ALLOWED permits a read.
3. Start an explicit local inspection session. It begins now, clears old observations and commits control/settings before showing readiness. Empty or invalid scope cannot start. Maximum 32 packages in this local prototype; source queries are explicitly filtered by package and resume/pause type. An empty set must never reach the API because Android interprets it as all packages.
4. Switch to selected apps, then return and tap Inspect now. This is a manual foreground read; no new read is admitted while the inspector is hidden. If an earlier read is still finishing, disable Inspect and explain that the user can tap it after the read ends. Returning or recreating the screen never queues or automatically restarts a read. Hiding cancels authority to retain its result, although an already-entered Android query may finish later. Show source status, observation times, bounded recent transitions and diagnostic duration estimates. Coverage remains unknown and estimates are not current attention, exclusive screen time, zero-use evidence or complete OAP summaries.
5. Stop clears observed activity and prevents further reads. Clearing selection also removes stored selected package settings. Starting again establishes a new consent horizon and does not backfill the stopped interval. Process restart is stopped and has no old activity to inspect.

## Authority and read boundaries

Local inspection consent is separate from recipient sharing and from Android's usage-access grant. No receiver or recipient grant is created. Reads begin no earlier than this session's original authorized start, no earlier than a bounded 24-hour horizon, and never from OS daily aggregate buckets. Query only selected package/timestamp/type data, redact every unexpected package before reading its other event fields, and do not access class names, labels, content, extras or interaction payloads.

Capture session/scope generation, lifecycle read epoch, usage-access notification revision and clock anchors before the query. Recheck actual OS permission, unlock state, foreground lifecycle, exact scope and generation after return and before displaying or ingesting observations. Require ready storage/change tracking, unchanged access revision, continuous clocks and an unexpired 24-hour session. Reject stale operation identity and authority before a returned permission-denied or device-locked status can stop or persist a different session. Cancel only the exact old query ticket; an old result cannot cancel a newer ticket. Scope changes, Stop, settings/storage failure and permission loss stop the session and clear RAM. Lifecycle hiding cancels pending logical authority without forcing a new consent horizon, so normal app switching remains usable. A new process always requires a new session.

Own physical source-read occupancy once per process, independently of each Activity's logical query authority. Reserve the sole slot before issuing a core query ticket. Refuse a busy explicit request immediately; never queue a replacement, an automatic retry or a read on resume/recreation. A reservation that has not been dispatched may be abandoned. Once dispatched, cancellation, Stop, Clear, a fresh Start or Activity destruction must not release its slot while source work is running. Release occupancy only when that source call actually returns, throws or is skipped before entry after cancellation. Completion delivery is separate: a finishing executor callback may reject a new dispatch safely, cancel its exact ticket and require a later explicit tap.

The source worker may retain the Application, a static pending-operation record, its query ticket/reservation and a synchronized foreground/epoch object containing primitive state. It must not retain an Activity, View, widget callback or per-Activity executor. Keep only the current screen observer and remove it by identity on Stop/Destroy. Before committing a completion on the main thread, verify exact current operation identity and all authority fences. If main-thread completion posting fails or throws, cancel only that operation's reservation authority and exact synchronized core ticket, record delivery failure, and reconcile it on the next main-thread report/request. Do not commit, persist, notify UI inline or automatically retry from the worker.

Use wall time for OS query timestamps and elapsed realtime to detect rollback, reboot/discontinuity and implausible drift. Unknown timing stops inspection and clears observations; a new explicit Start can establish new anchors. Query windows, projected event counts and acceptance/iteration have finite bounds; overflow suppresses the read with a safe reason rather than silently truncating an apparently complete result. The existing five-second source acceptance budget rejects late results but cannot interrupt an already-entered OS/Binder query or promise its wall-clock completion time. If source work never returns, this process remains busy; canceled authority cannot free the physical slot. A later manual Inspect is possible after actual return or a process restart, which returns to Stopped and requires a new explicit Start.

## Reconstruction and honest inspection

Pair only permitted package-level resume/pause observations after consent, with half-open timing and union semantics. Multiple activities or duplicate-looking transitions are ambiguous without instance/class identity. Do not guess a baseline idle state or fabricate a closing time at a query/window boundary. Missing starts/stops and conflicting transitions reduce usable diagnostic evidence. Same-package intervals may be merged only where justified; different packages may overlap.

A successful or empty query attests neither completeness nor initial state. Every diagnostic report declares unknown source coverage. Show no duration from a missing period as zero. Closed inferred intervals may be presented with that limitation; there is no OAP conversion or validity/consumption receipt. The earlier [synthetic model](../../src/android-observation-model.mjs) has fixture-only attestations that are unavailable here.

Label records as Activity resumed/paused and explain that internal screen changes can generate multiple transitions without an app exit. Show the number of inferred closed intervals and plain-language warnings for overlapping, missing, conflicting or still-open transitions. Never call the record count an app-visit count or join pause-to-resume gaps using a debounce threshold. Display at most eight recent closed intervals per selected package, with explicit truncation wording; label the total as the sum of all retained inferred intervals. When same-timestamp transitions or an unmatched pause explicitly invalidate prior estimates, display “Some estimates were discarded; this sum may omit parts of the window.” Do not present that remaining sum as a complete app-session duration or a lower bound on actual usage.

An optional controlled-test comparison is restricted in the UI and JVM comparator to the fixed package `org.liveabit.fixture`. The user manually enters the owned fixture's wall-clock start/end time codes and reported callback duration. Inputs stay in memory, are not saved/autofilled/exported, and clear on leaving the inspector, a fresh Start, Stop or scope change. Compare only already retained closed estimates clipped to a nonempty window wholly inside the current authorized session and the last successfully queried interval. Do not issue another query, backfill earlier consent or fabricate a closing boundary. If no closed estimate overlaps, show unknown rather than zero. Label a numerical result as the sum of retained inferred intervals in this window, and show the user-entered fixture value and signed difference without a pass threshold or coverage assertion. Show the report's existing plain-language ambiguity reasons in both numerical and unknown results, with the same explicit-discard warning where applicable. Manual values remain unverified, coverage remains unknown, and neither result is an accuracy pass. This is neither an authenticated fixture attestation nor proof of accuracy; see the [owned fixture specification](lifecycle-fixture.md).

The controlled fixture panel may contain a second, explicitly opened timing-details disclosure. Restrict its projected event and interval codes to `org.liveabit.fixture`; retain all original observation bounds and clear/hide these details with the comparison panel on lifecycle hiding, Start, Stop, scope mutation, permission/clock failure or Clear. Show existing session wall/elapsed anchors, last successful exclusive query cursor, actual report wall/elapsed pair, and display timezone ID/offset without recovering or inventing unavailable clock/query anchors. Label the report pair separately from a query-end clock. Show bounded exact epoch event/interval codes and honest shown/retained counts; a complete retained display still does not prove complete Android history. This adds no query, export, persistence, fixture attestation or coverage guarantee. Main inspection remains plain-language; technical codes are optional controlled-test details.

## Storage and app boundary

Keep at most 4096 projected transitions in RAM, with an active observation horizon no longer than 24 hours. Clear activity on Stop, scope mutation, fresh Start, process restart and authority/clock failure. Persist only bounded settings/control under getNoBackupFilesDir() in normal credential-encrypted storage, with explicit backup/transfer exclusions and no Direct Boot support. Corrupt/unknown or failed settings writes fail closed; no device identifier, token or raw observation is written to diagnostics.

The manifest contains usage-access declaration and the launcher activity only. No INTERNET, ACCESS_NETWORK_STATE, QUERY_ALL_PACKAGES, Accessibility, device-management, boot receiver, background service or exported data provider. No sharing/export button, endpoint configuration, analytics, automatic agent invocation or cloud library. Selected package preferences remain locally until Clear; Android's own history is outside the app's deletion control.

## Verification and next evidence

Run JVM core fixtures for scope redaction, no pre-consent history, ambiguity/open intervals, interval overlap, state/generation races, clock failures, bounds and process-reset semantics. Run separate coordinator regressions against the actual process coordinator and current core with an interrupt-ignoring blocked host source: repeated modeled screen replacement must retain one physical source call and zero queued replacements; Stop/Clear/fresh Start, access/epoch/clock/expiry changes and late denied/locked results must not ingest old events or affect a fresh session. Check undispatched rollback, executor rejection, old completion after new admission, failed completion delivery and worker failure. Execute Application admission/completion code with explicitly identified host substitutes in a separate suite; keep those substitutes outside APK source sets. Report modeled lifecycle and substituted Android/source/storage behavior honestly. Compiling against Android API/resource JARs is a type check, not Android runtime verification or Activity garbage-collection evidence. Inspect source and the eventual merged APK manifest for the absent network/inventory/enforcement surfaces. Build with pinned official tools and retain source/tool hashes plus exact outcomes; a source review or host regression does not satisfy a changed APK's emulator gate.

Physical trials must show permission denial/revocation, actual app selection, known controlled app switching, empty/unavailable history, screen lock, process kill/restart, scope changes and Stop. Compare reported diagnostic intervals with a consented fixture timeline, retaining omissions in the denominator. Background and battery quality measurements remain a later stage; this app makes no automated monitoring promise. Existing AC-02/04/05/07/18/19/25/26 associations are partial preparation until actual device observations are recorded. AC-29's no-intermediary boundary applies; absent networking does not establish a real direct host.
