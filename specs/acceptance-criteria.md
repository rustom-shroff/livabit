## Test setup and evidence format

Use synthetic observations, two recipient grants, distinct device/publisher identities, a controllable clock, deterministic retry randomness, restartable durable state, and fault injection. Persist a minimal manifest of specification revision, library versions, OS, configuration, fixtures, expected/observed results, and safe logs. Every test references requirement IDs through the [traceability matrix](requirements-traceability.md).

No real AI is needed for M1. The direct deterministic receiver evaluates validity and consumption, not human attention. Cloud-profile tests must use controlled public-HTTPS/DNS fixtures or injected network boundaries. Local-agent tests use an explicitly approved authenticated TLS destination in the chosen agent runtime; insecure localhost relaxation is limited to the isolated simulator development profile. Avoid real tokens and private usage in fixtures. Simulated endpoint/control behavior must be labeled as such and cannot be claimed as an existing host API.

Measurement alone is not a quality pass without those thresholds. Usage access is not evidence of blocking authority; accessibility/device-management restrictions remain excluded.

Development acceptance under [ADR-0010](../docs/decisions/0010-collector-accepted-and-chatgpt-dots-priority.md) is not a claim that AC-25/26 or M3 passed.
