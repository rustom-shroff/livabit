# Android feasibility measurement plan

Date: 2026-10-05. Status: local native collector/inspection implementation first, under [ADR-0009](decisions/0009-android-local-inspection-first.md) and [its specification](../specs/android/local-inspector.md). Agent selection is deferred until local findings, and Linux stays on hold. [Authoritative-source refresh](research/android-feasibility-2026-10-04.md) records the earlier facts/tool inventory; current build and device evidence must be reported separately. The production Android publisher still awaits verified direct M2 integration. [Roadmap](project-roadmap.md)

## Questions and selected candidate

Determine whether permitted package/timing events produce useful, honest foreground-duration summaries; how much coverage and delay background scheduling loses; whether offline local controls survive lifecycle failures; and whether a native direct adapter can preserve OAP's security boundaries. Each question receives its own result. An emulator pass cannot establish OEM battery behavior, and a mock receiver cannot establish M2.

## Execution sequence

1. **Prepare an isolated test environment.** Feasibility development/local probes are authorized by the priority amendment. Pin development tools before installation and follow any actual environment permission or licensing requirement; do not request the roadmap approval again. Identify an owned test device or emulator before device actions. Record exact build/tool/library versions and source hashes. Begin with owned test applications and a test profile containing no private activity. Select only those package IDs, leave network delivery disabled, and expose a local stop/delete control. No existing SDK/device is available in the observed workspace.
2. **Establish event reconstruction.** Generate controlled usage from fixture apps with their own timestamped lifecycle harness. Use only the known test-app package/type/time fields as ground truth; no screen recording or other-app lifecycle instrumentation is required. Compare package-only reconstructed unions with the fixture timeline. A daily OS total is only a rough cross-check, not precise ground truth.
3. **Prove consent and persistence.** Exercise local grant/pause/narrow/revoke and restart races with network disabled. Inspect the private state for permitted fixture data, immutable events, original deadlines and safe diagnostic categories. No app/class/content fields appear accidentally.
4. **Measure scheduling on physical devices.** Run matched 24-hour enabled/disabled trials, with screen-on/off, charging, network changes, Doze and ordinary user interactions recorded. Repeat before generalizing. Physical OEM measurements, not emulator scheduling, determine any support recommendation.
5. **Test synthetic direct TLS.** Use a final deterministic receiver and fake usage/credentials on an explicitly controlled endpoint. Keep collection disabled for this stage until its own results justify combining the stages. Exercise transport/authentication/receipt failures; the endpoint terminates consumption and never forwards. Real-agent compatibility is assessed separately at M2.

## Reconstruction and coverage experiment

The local [synthetic model](../src/android-observation-model.mjs) and [regression tests](../test/android-observation-model.test.mjs) exercise this reasoning on Windows before SDK work. `trustedStates` and `trustedContinuity` are explicit fixture assumptions, **not documented Android attestations**. A real collector must establish a permitted, defensible source for starting state and transition completeness. A successful query does not supply either. If that cannot be established, keep coverage unknown, suppress unsafe summaries and record the limitation; do not turn synthetic success into a claim that the collector is viable on a device.

Prototype a package-level resumed-count/union model using only permitted transitions. Multiple activities of one package must not double-count elapsed time; different packages may overlap. Do not assume every resume has a matching pause, that identical timestamp/type pairs are duplicates, or that package counters prove identity. Record ambiguous multiplicity, missing transitions and late-history effects as local source uncertainty. After ambiguity, a later pause discards inferred coverage since the last independent state; recovery requires a new trusted state. This conservative rule can suppress useful history. If package-only reconstruction is inadequate, narrow supported configurations or stop; do not read class names or add another sensitive API to rescue it.

Only trusted closed segments, or a checkpoint whose continuity is established for the tested source, may contribute duration. Do not carry an unknown open session across a consent start, reboot, corrupted checkpoint or clock discontinuity. After a fresh grant, an already-open app without an authorized known start remains unknown until a valid boundary establishes its state. Never query earlier unauthorized history or prorate a bucket. No new wire fields are needed for this conservative behavior. [OAP contract](../specs/protocol/oap.md)

| Case | Fixture and observation | Required result |
| --- | --- | --- |
| A1: Single app and handoff | 30-second, 2-minute and 10-minute sessions; A→B→A; rapid relaunch; session across a window boundary | Correct half-open clipping, no same-app double count; report measured error against fixture timing |
| A2: Overlap | Split screen, two activities of one package, translucent activity, picture-in-picture, drawer/ordinary lock | Preserve supported per-app overlap; distinguish resumed foreground from visibility; ambiguous state yields partial/suppressed output |
| A3: Authority boundary | Grant halfway through an existing session, pause/resume, narrow, expiry, Settings usage-access loss | No pre-grant/paused/denied observation read or export; unaffected recipient remains isolated; no paused backfill |
| A4: Source boundary | Empty query, query failure/null, process kill, reboot before/after first unlock, force-stop/relaunch, long collection gap | Unknown is not zero; no invented closing timestamp or complete-coverage claim; recovery retains original TTL |
| A5: Clock boundary | Forward/backward wall change, timezone change, sleep and reboot | UTC windows stay distinct; discontinuity reduces coverage/stops unsafe expiry operations; elapsed budgets cannot reset through wall changes |
| A6: Filtering and size | Empty allowlist; denied fixture app; 1/32/33/64 approved packages; coverage fragmentation | No denied identities/counters/labels; obey fixed partitions and negotiated cadence; overflow suppresses whole group rather than dropping apps |

Coverage applies to the whole approved scope. Intersect independently trustworthy observation intervals and clip every app to that common union; merge adjacent intervals. Use existing coverage reasons and the 64-interval limit. A successful/empty API query alone is insufficient evidence for `complete`. Retrospective delay does not automatically mean lost coverage if authorized history and continuity can be established; report delay and actual missing coverage separately. Finalized windows stay immutable if later OS data appears.

## Local control and storage checks

Use separate recipients with different allowlists, fields and cadence. Commit denial before canceling work, purging affected payloads and removing credentials. Capture a generation for each query and discard its result if authority changed before aggregation/commit. Introduce a blocking point after DNS/preparation and immediately before request credentials/body to demonstrate that a concurrent durable revoke prevents any new write. Show separately which request already began before the boundary. Cancelled workers, network restoration, reboot and credential renewal must not revive paused/revoked authority.

Test corrupted/absent consent, transaction failure, process exit during finalization/dispatch, missing Keystore key, reinstall/restore and authentication-required keys. Keep all activity/authority state unavailable before first unlock. Explicitly exclude state from backup/transfer and make unexpected restoration deny by default. A foreground UI and WorkManager must share authoritative state rather than maintain independently active permission caches. [Direct Boot](https://developer.android.com/privacy-and-security/direct-boot), [backup rules](https://developer.android.com/identity/data/autobackup), [OAP privacy/security](../specs/privacy-security.md)

Maintain the agreed default 15-minute windows, four fresh events/hour/recipient, 16 KiB/event, 64 KiB catch-up, 24-hour/4 MiB history and six attempts/cycle. Test bounded pruning while offline and stalled; diagnostics also have their own quota. Retention is measured from original observations/windows and shortened by current grant/subscription/credential expiry. Window replay, scheduler retries and app relaunch cannot extend it.

## Scheduling and transport measurements

Record separately: fixture event→API availability; window end→query; query CPU/wall time; window end→publication; publication→valid consumption; and any independently observed host evaluation/notification at M2. Preserve missed opportunities and suppressed windows in the denominator. Report p50/p95/max and the number of attempted, covered, expired, suppressed and consumed windows. Do not substitute the Windows transport p95 for Android end-to-end behavior.

Run an API 35/36/37 emulator compatibility matrix, then physical API 35+ devices from at least two OEM families, including the proposed pilot user's configuration. Record API/security patch/OEM, profile, power settings, force-stop state and network; avoid hardware IDs. Compare baseline and enabled trials for CPU time, wakeups, query count, worker duration, transmitted bytes and battery/energy where tools can measure it. APK/debugger/ADB instrumentation can alter power behavior; record instrumentation and repeat uninstrumented trials. No numeric Android accuracy/battery thresholds are agreed yet: propose them from measurements and obtain approval before claiming M3.

For target 37 LAN tests, include `ACCESS_LOCAL_NETWORK` denied/granted/revoked and the system-picker alternative only if the actual selected host/profile supports it. Public HTTPS needs no LAN permission. Include IPv4/IPv6, Wi-Fi/mobile handoff and a reachable LAN with no upstream Internet: a scheduler's connected/validated-network constraint must not be mistaken for receiver reachability. Test platform localhost cleartext/pin relaxation explicitly; the production adapter rejects HTTP regardless of those defaults. [Local network](https://developer.android.com/privacy-and-security/local-network-permission), [network configuration](https://developer.android.com/privacy-and-security/security-config)

Transport cases include wrong/untrusted/expired certificate, hostname/pin mismatch, public/private/mapped/reserved DNS answers, changing DNS and connected peer, endpoint/trust mutation after preparation, every redirect, automatic retry/proxy replay, lost/malformed/mismatched receipt, streamed oversize data, timeout and excessive `Retry-After`. Verify consent again before writing credentials/body, disable uncontrolled retries/redirects/alternate routes, and bound connect/total time to 10/30 seconds. Repeat the 100-accepted-summary synthetic healthy-transport benchmark on Android, recording its actual p95 separately from collector delay and the Windows result; the existing reference threshold is not a real-host SLA. Unsupported client controls or host endpoints stop that profile; no project-operated or separate user-hosted relay, tunnel or forwarding service, and no separate coach, is introduced. [Direct profile](../specs/protocol/profiles/direct-https.md)

## Evidence and next decision

Save a dated, local, token-free report containing source/tool hashes, consented fixture configuration, device support matrix, outcomes/known failures, safe timing distributions, coverage/error examples, storage/battery results and observed endpoint roles. Keep fixture-package details only in the deliberately consented measurement artifact; routine health logs omit app names and payloads. Export no private observations or bearer credentials and use no centralized telemetry.

The spike succeeds as research when it produces a reproducible answer about permitted collection, honest gaps and supported configurations, including negative results. It cannot complete M2 or M3. Proceed to the full Android product only after a real chosen-agent direct path is proven and acceptable Android quality/security thresholds are approved. Linux execution remains deferred under the user's revised priority.
