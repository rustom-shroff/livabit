# Optional task-aware companion trial

**Superseded trial design, 2026-10-15:** this dated task-only trial remains historical. Current support uses the user's existing main personal agent, optional intention/feelings inquiry, contextual goals and deliberate reconsideration under [ADR-0024](../decisions/0024-personal-agent-behavior-change.md) and [ADR-0025](../decisions/0025-durable-activity-analysis.md). Use the [current system guide](../current-system.md) and [conversation evaluation plan](../evaluation/personal-agent-conversation.md); no open task is required for support. Do not rerun the dedicated-agent setup commands below over a current personal-agent installation. New sender builds and physical background checks need their own evidence.

**Activity connection already confirmed, 2026-10-12:** The user reported **“OpenClaw acknowledged activity”** over Wi-Fi after correcting the address and applying the approved scoped firewall exception. [Confirmation](../review/openclaw-phone-delivery-2026-10-12.md). That trial's APK version/hash was not independently read. Earlier WhatsApp connection checks [arrived with notifications](../review/openclaw-phone-notification-2026-10-11.md). Those are historical results and remain separate from companion notifications and task-grounded coaching.

Updated: **2026-10-13**. Keep the current tested [liveabit Sender 0.11.0 APK](../../artifacts/android-publisher/liveabit-sender-0.11.0-poc.apk); [setup regression review](../review/android-setup-regressions-2026-10-13.md). The reminder destination now uses the official OpenClaw Android companion under [ADR-0023](../decisions/0023-openclaw-companion-reminders.md). Sender sharing state, startup restoration and direct activity connection remain unchanged. This optional trial evaluates useful coaching; local development can continue without another phone test.

1. In your existing main OpenClaw conversation, add an actual task you want help with. Include its priority, an explicit deadline if it has one, and a concrete next step. Main's personal-tasks Skill stores it in Workboard for liveabit to read. Example wording: “Add my job application task with high priority, deadline Friday and next step review the resume.” Use your real task details in OpenClaw; nothing needs to be pasted here. This uses ordinary tasks, not OpenClaw's internal Goal primitive.
2. Keep an existing working liveabit sender connection. If you have not installed the corrected 0.11.0 sender, install it over the existing app. For a new connection, generate it with `.\scripts\configure-openclaw.ps1 -AgentId liveabit -Lan` and transfer private `artifacts/openclaw/android-wifi-setup.json`. Keep the computer running and both devices on reachable Wi-Fi. Setup preserves models. [Connection guide](../../android/publisher-app/README.md).
3. Connect the OpenClaw companion to your gateway and allow notifications. If the initial migration has not been applied, run `.\scripts\configure-openclaw-companion.ps1` then `.\scripts\configure-openclaw.ps1 -AgentId liveabit`. These retain preferences/delivery state, disable owned old WhatsApp policies, apply updated instructions/tool access and restart the managed gateway without changing models. Existing sender sharing stays on without another Start; a previously stopped sender stays stopped. For new sender setup, import its file, **Connect to OpenClaw**, choose apps/permissions and Start sharing once. Import/check alone does not start sharing. [Companion guide](openclaw-companion-notifications.md).
4. Use a selected app normally, return to liveabit and tap **Send now**. Only positive selected-app duration produces an OpenClaw packet; “nothing sent” is expected when no meaningful monitored activity is available. When activity is sent, look for admission acknowledgement and inspect the receiving liveabit conversation. Admission is distinct from interpretation.
5. Let liveabit consider open tasks, priority, deadline and next step. A useful companion notification is selective, rather than a receipt for every observation. No task or insufficient context means silence. Default policy is a 60-minute cooldown and quiet hours 22:00–08:00 America/Chicago, with existing preferences preserved. Synthetic checks and duplicate observations do not justify nudges. Native invocation acknowledgement and visible Android notification are separate outcomes. [Companion policy](openclaw-companion-notifications.md).

Automatic activity sends target five minutes and pause after fifteen minutes screen-off; both are configurable in Settings. Closing the app leaves sharing enabled. After phone shutdown/restart and the first unlock, monitoring resumes without opening liveabit; previously stopped sharing stays stopped. Android may delay jobs, and Force stop blocks background work until reopening. Stop sharing cancels scheduled sending and clears pending activity. Receiver warnings default to 60 minutes without acknowledgement and are independent of companion reminders. Keep the companion connected to the gateway; offline notification recovery is unverified. Precise duration, complete coverage and battery behavior remain deferred or unproved.

## Next steps

Development can continue independently; no approval or required phone test blocks it. Use main in the companion to manage real tasks and keep the companion connected with notifications allowed. No new APK or sender setup import is needed for the reminder-route change. Reporting whether a notification appeared and whether a task suggestion was useful is optional; keep keys, task details and raw activity private.
