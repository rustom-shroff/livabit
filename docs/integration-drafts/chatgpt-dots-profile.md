# Proposed ChatGPT dots Events profile

Date: **2026-10-07**. Status: **ChatGPT dots selected as product target; proposed runtime profile disabled; no real-host pilot or M2 evidence**. Tentative profile: `openai-mcp-events-v1`. This packet proposes CP-HOST-01/02/03/04 for review; it changes no approved schema, interface, authentication policy or executable adapter.

The user accepts the current Android collector for continued development. Further precise-duration and complete-coverage proof is deferred. Its unknown-source diagnostics remain local inferred observations, never synthetic ground truth or validated OAP summaries. The pilot starts with schema-valid synthetic OAP pages, preserving [OAP 0.1.0](../../specs/protocol/oap.md), [authorization](../../specs/protocol/authorization.md) and [delivery](../../specs/protocol/delivery.md).

## Documented foundation and topology

OpenAI documents Events for dots, using MCP 2.0 dated `2026-07-28`. One authenticated endpoint supports `server/discover`, `events/list`, `events/subscribe` and `events/unsubscribe`. Subscription identity includes authenticated principal, event, filters and callback identity. The HTTPS callback challenge precedes application data; signing material uses a `whsec_` prefix and base64-encoded 24–64-byte secret. Standard Webhooks signs exact transmitted bytes; retries retain event ID and immutable body. Callback `2xx` acknowledges receipt while processing is asynchronous. The whole native event cap is 256 KiB; `410`/`413` are not retried. Finite refresh, rotation and unsubscribe need lifecycle handling. [Events guide](https://developers.openai.com/plugins/build/mcp-events)

Secure MCP Tunnels provide provider-owned private ingress with a device-local tunnel client, runtime key, tunnel ID and workspace/Platform permissions. Private custom MCP testing is supported; public plugin distribution is not. Android packaging and Events-through-Tunnel composition are unestablished. [Tunnel guide](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

Proposed topology: the **producing device** owns synthetic publisher, consent/outbox, authenticated MCP endpoint and tunnel client; OpenAI owns private ingress, dot control and callback infrastructure. Windows-only synthetic testing is legitimate reference development. Android publication through a desktop endpoint/client is excluded forwarding. No public proxy, project authorization server, separate bridge or independent API coach is introduced. Failure of same-device connectivity stops this route under [AC-29](../../specs/acceptance-criteria.md).

## Proposed amendment packet

**CP-HOST-01 — receipt policy.** Add a tagged `receipt_only` result alongside existing [ValidConsumptionReceipt](../../specs/protocol/interfaces.ts), preserving [direct-profile H5](../../specs/protocol/profiles/direct-https.md). Proposed successful callback handling atomically records transport acknowledgement, stops automatic retries for that event and retains bounded correlation/history under original deadlines. Lost acknowledgements remain unknown, with bounded same-body retries. No native response sets consumption, evaluation or notification timestamps. Review publisher/status/conformance changes together; fabricate no consumption receipt or host ledger evidence.

**CP-HOST-02 — authentication and authority.** Specify separate tunnel-access, incoming MCP-principal and callback-signing authorities. Tunnel association alone proves none of the others. Protected pairing binds verified provider origin/callback, actual existing dot recipient, device, local grant, OAP stream/scope epoch and native subscription; secrets remain opaque protected handles. Subscribe/refresh arguments may only narrow approved scope/cadence. Local denial commits offline before cancellation/purge; every control/read/send rechecks consent. Bound lifetime by local grant, actual native expiry and applicable credential deadlines. Prove rotation/old-secret rejection and supported unsubscribe. Document receiver admission differences from [A3/A5](../../specs/protocol/authorization.md); local filtering cannot substitute for server enforcement. No invented issuer/refresh API.

**CP-HOST-03 — capabilities and pairing.** Propose the profile ID in the [capability schema](../../schemas/oap/0.1.0/capabilities.schema.json) and `DeliveryProfileId` only after review. Pin host schemas, protocol/client versions, limits and supported event recovery. Native discovery is not an authenticated OAP capabilities response: define a reviewed mapping and real-account eligibility check. Missing authentication, eligibility, ingress or lifecycle support leaves the profile unavailable. Preserve existing direct profiles and [conditional MCP gate](../../specs/protocol/profiles/conditional-mcp-events.md).

**CP-HOST-04 — event mapping.** Define the proposed native event as **an immutable OAP page became available**, rather than an app-use occurrence. Map that page unchanged into native `data`, `eventId` to OAP `event_id`, and native `timestamp` to its original `emitted_at`; keep source/window/occurrence times inside the unchanged OAP page and signing time separate. Keep native/OAP subscription IDs distinct. Canonicalize filter/callback identity for idempotent subscribe/refresh, verify callback before activation, and test rotation/unsubscribe. Preserve TLS/destination checks, redirect rejection and callback identity across reconnect. Wrapper accounting cannot relax 16 KiB/page, four fresh events/hour/recipient, six attempts/cycle or 24-hour/4 MiB history. No invented gap event, cursor or replay API; keep unsupported recovery and incomplete groups explicit.

## Bounded pilot and observable outcomes

1. **Prepare offline:** review the packet and synthetic envelope/signature/response fixtures; executable profile stays disabled until agreed changes exist.
2. **Establish eligibility:** identify the user's existing dot, supported private plugin/event access, workspace permissions and same-device client availability through protected human setup. Keep credentials out of chat, source and logs.
3. **Prove control:** synthetic data only; observe authenticated discovery, idempotent subscribe, callback verification, finite refresh, rotation, reconnect/restart and unsubscribe. Audit destinations and offline pause/revoke; failed proof stops activation.
4. **Observe delivery:** send one authorized synthetic page at compliant cadence. Record event digest/version, receipt, independently observed evaluation and user-visible response or silence separately.
5. **Exercise bounds:** test duplicates/lost acknowledgement, changed-body rejection, delay/out-of-order/expiry, gaps/unknown coverage, incomplete page groups, malformed/oversize input, invalid credentials, rotation/narrowing and outage/revoke races. Check no repeated intervention, inferred zero, premature group completeness or prompt execution from labels.
6. **Report:** retain per-case pass/fail/untested outcomes and limitations against AC-22/23/24/28/29 and [OAP-FR-011/014, OAP-NFR-009](../../specs/product-requirements.md); no M2 claim until actual evidence satisfies the reviewed gate. Android transport/lifecycle and distribution remain separate unproven work; Linux stays deferred. Changed phone-trial APKs retain their exact-byte emulator-first gate.

Dots document existing context/memory and user-requested event monitoring, but this pilot has observed no such behavior. [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory) Existing standing instructions decide appropriate advice, missing-context uncertainty, quiet periods and intentional-leisure silence; private goals/memories are not exported into the device-local activity publisher, packets or logs. Precise collector accuracy remains deferred, without weakening privacy, consent, security or resource bounds.
