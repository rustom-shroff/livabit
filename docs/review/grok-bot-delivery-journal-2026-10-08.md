# Grok Bot local delivery journal development

Date: **2026-10-08**. Scope: **offline authored fixtures and device-side delivery accounting preparation**. The user's instruction to keep building authorizes this local work without an account, purchase, approval or phone trial. Grok remains the selected target under [ADR-0014](../decisions/0014-resume-grok-bot-direct-webhook.md). The preceding [local admission development](grok-bot-local-admission-2026-10-08.md) retains its exact source and evidence.

The [new journal](../../src/experimental/grok-delivery-journal.mjs) uses the unchanged strict protocol parser/validator, canonical digest, transactional store and [Grok outcome classifier](../../src/experimental/grok-webhook-outcome.mjs). It retains immutable synthetic pages under a fixed `test.app` binding. One irreversible reservation per page is committed before any RAM-only local fixture handle is exposed. The same transaction spends the rolling-hour budget. Outcomes remain terminal; HTTP 200 is only the modeled run-start report. No valid OAP consumption receipt or host evaluation is invented.

Actual file reopen preserves page identities, original expiry, terminal results and spent budgets. Unfinished reservations lose their RAM handle and remain uncertain/blocked. There is no automatic retry, renewed page identity or inferred no-body result after restart. Current local control and generation determine consent at outcome recording; pause/resume cannot retroactively renew authority for an earlier reservation. Revocation is irreversible and removes stored bodies. Expiry cleanup occurs on open/access, including denied operations, while bounded metadata tombstones remain. The limits are 64 retained identities, 1 MiB and four reservations in a rolling hour, with no silent eviction or replacement store.

Independent review closed concrete gaps before final verification: nested fixture getters are refused without execution, cross-entry window/group consistency is rechecked, and a lost transaction return removes any installed handle while leaving the durable reservation held. Denied operations commit expiry maintenance without committing their failed mutation. This journal opens no server or network connection, captures no credential, creates no account action and invokes no Skill/model. It is **not wired to the retained Grok probe**: that probe creates its own event internally and has no reviewed durable reservation fence. The journal does not harden or wrap that probe. Native raw-body mapping, actual credential/recipient binding, supported host execution/storage/concurrency and observed admission/evaluation remain unverified; production profiles and Android publication stay disabled.

The tested scope has one owning process and store instance. File reopening does not prove sudden power-loss survival; Windows `JsonStore` lacks directory fsync. Digest consistency does not protect against coordinated malicious rewriting. Store cleanup cannot erase returned body copies, transient JavaScript copies or provider-held records. Disposal retires the local object/handles and cannot undo committed work. No model callback or remote-cancellation promise is added.

The accepted Android APKs, native sources, Skill/dots/Grok/Muse history and previous admission evidence remain unchanged. Linux and further collector accuracy proof remain deferred. Any future changed phone-trial APK still requires exact-byte emulator validation first.
