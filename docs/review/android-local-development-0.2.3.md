## Changes and purpose

The collector previously checked wall-clock versus elapsed-clock agreement only since its latest report or query. Several small clock adjustments could each remain inside the two-second tolerance while their total drift from the original session exceeded it. The [collector core](../../android/collector-core/src/main/java/org/liveabit/collector/core/LocalInspectionCore.java) now checks both the latest and original session clock anchors. Its pure snapshot timing fence applies the same rules before a foreground source result can be accepted. This does not authorize a read or attest source coverage. Crossing the unchanged 2,000 ms tolerance stops the session, invalidates pending reads and erases observations; a fresh explicit Start establishes new anchors.

The optional controlled-fixture panel adds a hidden timing-details control for `org.liveabit.fixture`. It displays already retained fixture transition timestamps and inferred interval boundaries as numeric wall-clock codes, original session wall/elapsed codes, the last successful query cursor and the separately sampled report wall/elapsed pair. The **query cursor is an exclusive wall-clock boundary**; the app does not invent an elapsed-clock code for it. The current display timezone and report-clock UTC offset describe formatting context, not proof of the source timezone when an event happened.

The details filter records to the owned fixture even if other apps are selected. Explicit all/latest counts disclose the existing recent-record and interval display limits. Values remain in RAM and are cleared or hidden with the fixture panel, leaving the inspector, Start, Stop, permission loss, scope changes and process restart. The control issues no additional usage query, saves no observations and provides no copy/export or agent path. It adds no observation field to the Android source, permission, network dependency or intermediary infrastructure.

The local inspection specification was revision 0.5 for this release; the [frozen API 36 native audit](../../artifacts/android-emulator-0.2.3-api36-final/native-validation.json) retains its source binding, while the [live specification](../../specs/android/local-inspector.md) has since advanced for 0.2.4. Revision 0.5 describes the optional timing view and session clock guard. The inference policy and [fixed-package comparator](../../android/collector-core/src/main/java/org/liveabit/collector/core/FixtureComparison.java) remain unchanged. Same-time transitions and unmatched pauses still discard earlier estimates. Numerical results remain sums of retained inferred intervals, with explicit partial warnings and unknown source completeness; they are neither complete app-session durations nor lower bounds on actual usage. Manual fixture inputs remain unverified and no accuracy threshold is assigned.
