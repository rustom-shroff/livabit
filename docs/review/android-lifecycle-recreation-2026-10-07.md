# Android lifecycle recreation check

Date: **2026-10-07**. The exact inspector **0.2.4** passed this separate check once on each owned Android 15/API 35 and Android 16/API 36 emulator, after its [ten ordinary workflows on each image](android-local-development-0.2.4.md) had completed and been frozen. Both results are **`pass_with_synthetic_work_limits`**. No production APK or source was changed to run the check.

## What actually ran

A separate framework instrumentation APK loaded the installed inspector's existing Application, coordinator, executor and screen. It activated the existing Start control programmatically on the main thread for the fixed owned fixture, then submitted one bounded synthetic `Work` to the actual production coordinator. It did not create a production pending usage read or request a UsageStats query.

While that task waited on a test-owned latch, the controller requested two real `Activity.recreate()` operations. The recorded Android callbacks show destruction of the old instances and creation/resumption of new ones. Each new screen retained the same Application/coordinator and unchanged selected scope, session generation, original wall/elapsed anchors and exclusive query cursor. The old foreground authority was revoked, the new authority was distinct, Inspect was disabled and the existing busy message was visible. Replacement task admission remained refused.

Canceling only the test-owned reservation left the physical slot occupied while the worker remained entered. The controller then released its latch; the worker exited once and the slot became available. A third real recreation rendered Inspect enabled without the busy message. Each run recorded **four created and three destroyed screen instances, one worker entry and one worker exit**. The controlled worker was held for **1,345 ms on API 35** and **1,173 ms on API 36**. It did not hit its self-release deadline. These short controlled checks are not extended lifecycle stress trials.

## Binding, limits and cleanup

The [reviewed root driver](../../artifacts/android-lifecycle-probe-root-review/run-76034471-73d8-4c2c-9133-6f0ff378a854/run-owned-probe.mjs) checked both frozen ordinary gates, their complete indexes, all 56 audited native inputs, SDK/image/startup identity, exact owned launcher/QEMU command lines, guest identity, current user, account-free state and permitted initial foreground owner. It pulled and hashed the installed inspector, fixture and test APK before instrumentation. Inspector SHA-256 remained `df5ae7d7aad1c53818d9ce9812f49a3213c8b02e47caf2f2807f7abc130e6d6c`; test APK SHA-256 was `c5009afeac9ae31e470c27db634335a2732ef57361fddbfa843c33c3f953502d`. The test APK has no permissions or activity/service/receiver/provider declarations and contains only test-owned classes, with no copied production implementation or production debug hook. The native audit binds the unchanged APK signatures and permissions.

The [frozen test proposal](../../artifacts/android-lifecycle-probe-proposal/run-ebe07546-2c71-4e75-8379-650f8a5e7a3a/proposal-proof-final.json) preserves the build and independent pre-runtime review. Its [parser correction](../../artifacts/android-lifecycle-probe-proposal/run-ebe07546-2c71-4e75-8379-650f8a5e7a3a/PARSER-CORRECTION.md) records an impossible global lifecycle-order acceptance found before runtime; the corrected parser rejects it. Earlier proposals and build failures remain preserved. The authoritative parser passed two synthetic positive records, 31 record negatives and four transport negatives before these actual runs. Parser output is local validation, not cryptographic runtime attestation.

Work has a **45-second** self-release bound, controller a **100-second** budget and watchdog a **110-second** limit. The root's actual instrumentation commands had a separate **120-second** external timeout. These bounds do not hard-cancel a blocked Android OS/Binder operation. Cleanup releases only test-owned work, removes callbacks, stops the owned inspector and uninstalls the test package. Both runs completed without transport error, self-timeout, cleanup failure or an owned-package crash-buffer entry.

API 35 reused its already tested guest. API 36 used a fresh boot and [separate readiness/install record](../../artifacts/android-lifecycle-probe-preflight/run-0d8fdcd1-47ee-489e-ac35-f0af59fb2b85/validation.json). Running it with the compatible existing PowerShell 7 runtime succeeded; no startup-source change was made.

The root's [read-only final review](../../artifacts/android-lifecycle-probe-root-review/run-76034471-73d8-4c2c-9133-6f0ff378a854/final-evidence-review.json) rechecked 282 file bindings, both sets of original commands/observations, cleanup records and exact API 35 timing/replay mathematics without another test execution.
