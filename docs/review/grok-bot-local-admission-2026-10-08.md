# Grok Bot local admission development

Date: **2026-10-08**. Scope: **offline authored fixtures and local durable receiving preparation**. The user's instruction to continue local development requires no account, purchase, approval or phone trial. Grok remains the selected existing-agent target under [ADR-0014](../decisions/0014-resume-grok-bot-direct-webhook.md). This work opens no receiving server and sends no activity to a provider.

The [new experimental facade](../../src/experimental/grok-routine-admission.mjs) reuses the accepted [receiver](../../src/receiver.mjs), [strict protocol parser/validator](../../src/protocol.mjs) and [transactional store](../../src/storage.mjs) without modifying them. The trusted local fixture driver provisions synthetic `test.app` authority first. Admission authenticates that exact device/recipient/stream/scope binding, parses the entire raw JSON body and commits through the existing receiver before returning a **local OAP receipt**. That receipt is separate from Grok's native HTTP 200/run-start report; it establishes no native authentication, host evaluation or M2.

The separate `inspect()` operation returns a fresh view of owned, durable observations. It checks authentication on both sides of the snapshot, reconstructs each stored page and revalidates its scope/schema and original digest. Original window, emission and expiry times are retained. Missing pages and sequence gaps remain explicit. Complete page delivery does not turn partial source coverage into complete coverage. Expired groups stay unavailable even while retained for duplicate detection. The view includes no labels, extensions, goals, memories or private standing instructions.

An independent review found a concrete integrity gap during development: the frozen receiver discards optional labels/extensions, so the first projection could not compare its reconstructed event with the original ledger digest. The final facade refuses these optional fields, including an empty `extensions` member, before consumption. This stricter experimental restriction leaves OAP 0.1.0 unchanged and permits exact digest reconstruction. An in-range duration alteration now fails closed. The independent review approved runtime SHA-256 `55ef98a05d4361b017646fbd1668f81dab94c2e3ad938b33e556f9c67753cda3`. The digest detects inconsistent retained data; it supplies no defense against a local attacker rewriting both content and digest.

The [fixed exercise](../../scripts/exercise-grok-routine-admission.mjs) passed **11** authored checks without network or account access. It recorded acceptance, concurrent duplicates, immutable conflicts, duplicate JSON keys, wrong recipients, optional-field refusal, missing pages/gaps, out-of-order assembly, partial coverage, actual file reopen and original-expiry denial. The [exercise record](../../artifacts/grok-routine-admission/run-99d3146f-767e-4eb8-a3c0-a30d6b864e1b/exercise.json) preserves its synthetic views separately from the [previous Grok resumption](grok-bot-resumption-2026-10-08.md).

All **25 focused tests passed**. The full suite completed with **313 passed, zero failed and one existing skip** (314 tests total) on Node.js **v24.19.0**, in 28,775.2176 ms. The skip remains the device-local consent-pause fixture that a receiver validator cannot observe; separate publisher lifecycle tests retain that authority boundary. The suite covers raw-body/parser bounds and copied input bytes, distinct device bindings sharing identities, exact duplicates after actual file reopen, partial pages/coverage, original expiry, untrusted/rolled-back clocks, credential and snapshot races, invalid and schema-valid stored corruption, safe storage failures, disposal and no-input CLI behavior. CLI help and rejected-input checks instrument network APIs and verify no new evidence directory or secret-marker output.

The contract check preserves **nine schemas, 86 fixtures, eight groups, 33 requirements and 29 acceptance mappings**. Focused/full-suite transcripts, contract outcomes and unchanged historical source/output bindings are recorded in the [validation record](../../artifacts/grok-routine-admission/run-root-local-development/validation.json). These results establish only the stated local fixture scope.

The model supports one owning process/store instance. It is not safe to deploy separate concurrent Grok routine processes against this file. Inspection is separate from any earlier receipt and does not fence a future model invocation. There is no Skill callback, scheduler or exactly-once evaluation guarantee. `dispose()` retires this object and clears its token buffer; it does not revoke provisioned authority or undo an already-entered durable transaction. Actual authority withdrawal requires receiver rotation/expiry. JavaScript string copies and filesystem permissions retain the existing local reference limitations.

Actual raw-body availability, trusted native invocation identity, recipient isolation, supported host execution/storage/concurrency and observed evaluation remain unverified. No production native profile, publisher adapter, account action or paid alternative is enabled. The accepted Android inspector/APKs, frozen Grok/Muse/dots/Skill evidence and historical decisions remain unchanged. Linux stays deferred; further Android accuracy proof stays deferred. Any future changed phone-trial APK still requires exact-byte emulator testing first.
