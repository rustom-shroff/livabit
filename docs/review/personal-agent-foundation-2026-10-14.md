# Personal-agent foundation review

Date: **2026-10-14**. Scope: the project reorientation and first native OpenClaw evidence/conversation foundation under [ADR-0024](../decisions/0024-personal-agent-behavior-change.md). Source is implemented and locally tested; the final immutable bundle is installed and its native tools and authenticated hook were exercised. Real phone display, conversation quality and behavior change remain unverified.

The user authorized tested changes to the running setup, selected the existing OpenClaw companion chat for conversation, and asked to keep automatic accountability emails disabled. The Android collector/sender and OAP contract are retained. The new foundation uses the existing personal main agent and preserves its models, reasoning, unrelated instructions, native capabilities, Workboard and private companion preferences.

## Local evidence

The focused evidence/delivery suite passes 33 independent cases, the configuration suite 15 and the real-installer subprocess suite 12: **60 passes** using synthetic input, private temporary SQLite state and a fake native CLI. These cover canonical observation validation, persistence before forwarding, pending retry versus decided replay, conflicting identity, overlap/day-boundary/DST summaries, original raw expiry and separate bounded derived retention, episode ownership/provenance, native delivery outcomes, opt-out/timezone/freshness/cooldown, uncertain one-attempt handling and invocation revocation. Earlier attempts remain counted after the returned narrative is truncated; pre-invocation cancellation or changed preferences record suppression rather than a fictitious send. Configuration tests cover additive planning, fixed persistent routing, preservation/refusal and managed instruction updates. Installer cases exercise successful offline-phone migration, fresh bound-inventory preparation, cold-update ordering, failure rollback and preservation of concurrent owner changes.

Commands: `node --test test/personal-agent*.test.mjs`, `node --test test/*.test.mjs`, `node scripts/validate-spec.mjs`, PowerShell syntax parsing and `git diff --check`. The broader suite passes **433 of 434 cases**, with its existing S12 fixture excluded because receiver authorization cannot observe device-local pause/permission/collection authority; zero failures. Restricted-sandbox runs cannot exercise some existing temporary-file and loopback cases; the full result uses the bundled runtime outside that restriction. Specification validation passes 9 schemas, 86 fixtures, 8 groups, 33 historical OAP requirements and 29 historical AC mappings. PA cases remain separately traced.

These local tests invoke no real agent, send no real notification and do not establish physical display, conversational quality or behavior change. No APK or dependency change required an Android rebuild.

The test uses a reflection decision that cannot authorize sending even if the phone reconnects.

Positive-event model execution and physical delivery still need actual observation after the phone reconnects.

Failed attempts restored authored files while retaining private diagnostics. A first post-start probe timed out; gateway health and the subsequent full native check passed. OpenClaw's `plugins validate --entry` applies to newer authoring metadata rather than this mixed registration object; no success for that separate command is claimed.

## Limits and remaining work

The model owns behavioral interpretation and adaptation. The two-support-decision marker is an advisory heuristic, not researched optimal dosing. Calendar/email connections are not added. Questions use a passive companion invitation, followed by the user's ordinary main chat; inline replies, automatic reply linkage, proactive follow-up scheduling, failed admitted-model-run recovery and offline delivery queueing are not implemented.

Native acknowledgements are distinct from display/reading. Derived usage retains unknown coverage/unverified quality; overlapping and local-midnight-crossing windows are excluded without proration. The host keeps raw bodies to original expiry, estimates to 30 days and episodes to 90 days by installed default; startup/60-second cleanup needs the enabled plugin, valid settings and available gateway. Logical deletion does not claim forensic erasure from journals/backups or native conversations.

The plugin offers no external email route. Its activity instructions keep automatic accountability email disabled while preserving the personal agent's unrelated native capabilities; this does not independently isolate all inherited tools. Historical OAP/Android evidence, formal M2/M3 and long-term usefulness remain separate.
