# Task-aware liveabit and Android 0.9.0 review

Date: **2026-10-13**. Scope: the native Android sender and the user's installed OpenClaw 2026.9.9 gateway. [Machine-readable evidence](openclaw-task-aware-2026-10-13.json). [Decision](../decisions/0021-task-aware-liveabit-agent.md).

The exact **0.9.0-poc** APK (version code 11, 167,008 bytes, SHA-256 `11a99ae5440a3ea6c4024f21f6c832cba8ad0abf69833accf581ea8f2f80df64`) passed **80 native Android 15/API 35 emulator checks**. The suite installed those bytes and verified delivery to an isolated final receiver and the installed OpenClaw gateway. Build and lint completed with zero errors. Setup, Activity and Settings captures were visually inspected.

Setup exposes the three requested connection choices, with manual fields/help nested inside the editor. Activity omits the old setup shortcut. Native tests cover immediate connection success/failure status and dialogs, including wrong keys, unknown routes, unreachable/unresponsive receivers, and checking while the delivery worker is busy. The authenticated empty-object probe verifies the known hook response without admitting an agent run or changing activity/outage state.

Manual and automatic OpenClaw sends require positive foreground duration in at least one selected app. Empty, null, zero and transition-count-only observations produce no request. Tests also cover removing legacy empty queued reports while preserving meaningful retry bytes, identities and outage state. Previously meaningful pending reports remain retryable during a quiet collection window. The experimental OAP draft-2 contract and its draft-1 compatibility remain unchanged.

The installed `/hooks/liveabit` mapping targets persistent `agent:liveabit:main`, with automatic announcements and caller-selected sessions disabled. The dedicated agent and main retain the user's **openai/gpt-6.1-sol / medium** settings. A separate local operator verification completed using `gpt-6.1-sol` and actually invoked `workboard_list`; it returned **zero open tasks**. The native shared Workboard RPC independently returned an empty task list. No personal task content was exported, no task was created or changed, and external messaging was disabled for that verification.

The main agent's personal-tasks Skill manages canonical Workboard cards; liveabit has read/list access and considers real priority, explicit deadline and actionable next step. Completion deadlines are stored in card notes because this release has no native completion-deadline field. Execution `scheduledAt` is not a deadline. This uses ordinary personal tasks, separate from OpenClaw's session Goal feature. Task edits respect the native specify tool's status-changing limitations.

The installed final gateway transform returned HTTP 204 with no agent admission for an empty/transition-only report, HTTP 400 with the exact missing-message response for the connection probe, and HTTP 401 for a bad key. Four focused tests of this actual gateway module passed, including positive original-message forwarding and stale/malformed suppression. This module runs inside OpenClaw; it is neither a relay nor an Android sender prototype.

The final setup helper completed its actual gateway health check after one managed restart. Fresh native Android activity then reached the final dedicated mapping. The helper waits for HTTP readiness after the port binds and compresses bundled instructions to fit Windows' command-length limit. Dedicated instructions use a managed section that retains custom content; main instructions remain untouched.

The dedicated agent has a private verified WhatsApp self-chat policy. Its selected-agent settings helper was applied without a test send, confirming the linked account's own identity and preserving omitted preferences and delivery state. Existing cooldown, quiet hours, processed identities and user model choices are retained. Main task data remains inside OpenClaw. Earlier WhatsApp phone notifications and Wi-Fi phone admission are separately [user-confirmed](openclaw-phone-notification-2026-10-11.md) and [recorded](openclaw-phone-delivery-2026-10-12.md); they do not establish a new task-grounded coaching message from this revision.

The isolated receiver and project-owned emulator were stopped after validation; OpenClaw remains running. No physical phone was installed or changed by these tests. Precise duration, complete coverage, battery performance, exact Android scheduling and usefulness of real coaching remain unproved. Quiet hours, cooldown and nudge selection are best-effort agent policy. A missing task or insufficient context means silence; the examples in documentation were not added as real user tasks. No hosted intermediary, new firewall/router change or JavaScript sender prototype was introduced.
