# Phase 4 reference implementation review

Date: **2026-10-04**. Contract: **Open Activity Protocol (OAP) 0.1.0**. Selected runtime profile: **direct-loopback-test-v1**. The optional agent skill remains named **liveabit Skill**.

The user agreed to the Phase 3 contract and authorized the reference implementation on 2026-10-04: “ok keep going if there is no further input required from my side”. G1 is agreed. The approved no-intermediary design and immutable-finalized-window refinement remain in force.

The Windows reference exercises a real direct HTTP receiver, durable device and receiver state, consent/recovery controls, and separate publisher-process exits/restarts. The recorded suite, two-process direct demo and local benchmark identify the actual Node version in the [runtime manifest](phase-4-validation.json). Evidence is retained separately for each tested platform and Node major. The user **accepts the Windows M1/G2 reference baseline for progression** under [ADR-0008](../decisions/0008-windows-baseline-and-android-integration-priority.md). Linux portability is untested and on hold. Direct integration/skill and Android feasibility work may proceed; actual M2/M3 behavior is not claimed.

## Release decision and remaining work

The implementation preserves the direct topology: one simulated device publisher/adapter and one final deterministic receiver, with embedded state and no model or intermediary service. Local HTTP is an isolated test exception. TLS safeguards are present in the adapter, while the shipped mock receiver remains a synthetic loopback reference.

The accepted [priority change](priority-change-2026-10-04.md) supersedes the earlier Linux progression prerequisite. The [portable Linux handoff](../linux-verification.md) stays parked; no Linux setup is needed now. The subsequent [2026-10-05 decision](../decisions/0009-android-local-inspection-first.md) puts the native local collector/inspection first and defers real-agent selection. Production/profile deployment, actual M2 and Android M3 need separate evidence. The [dated host follow-up](../research/direct-host-follow-up-2026-10-04.md) retains a native Workspace Agent candidate without selecting a profile.

Production deployment additionally requires protected credential storage and authenticated real receiver onboarding. JSON snapshots have one owner per file; concurrent writers, Windows ACL security, all-filesystem crash behavior and power-loss guarantees are unverified. The reference exposes no Android background worker, device action, real host API, user goal/memory store, centralized activity logging or delivery subscription service.

An incompatible commercial host stays unsupported. Neither free hosting, a public proxy, a third-party tunnel nor a separate user-operated forwarding bridge is introduced to pass a gate. The user's existing host subscription or network costs remain separate from the project's lack of delivery infrastructure.
