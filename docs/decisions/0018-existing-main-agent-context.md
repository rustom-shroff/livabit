# ADR-0018: Send activity to the user's existing OpenClaw agent

**Phone confirmation, 2026-10-11:** The user reported that both WhatsApp connection-check messages arrived with a notification. [Confirmation](../review/openclaw-phone-notification-2026-10-11.md). Use the existing tested 0.6.0 APK for the [real-activity phone trial](../integration-drafts/openclaw-phone-pilot.md); its bytes are unchanged.

Date: **2026-10-11**. Status: **implemented in 0.5.0; native emulator delivery and main-agent output verified**.

The user selected their existing OpenClaw `main` agent for goals and context. The dedicated `liveabit` agent proved the direct path under [ADR-0017](0017-openclaw-direct-integration.md), but its separate workspace does not establish access to main context. Preserve 0.4.0 and its [evidence](../review/openclaw-poc-2026-10-11.md) as that baseline. Unreleased 0.4.1 work is included in **0.5.0-poc**.

Continue direct Android -> installed OpenClaw delivery. Native **`/hooks/liveabit`** configuration fixes main and its canonical conversation key, with `sessionMode: persistent`, `messageTemplate: {{message}}`, `wakeMode: now` and `deliver: false`. The mapping runs inside OpenClaw and adds no bridge; caller-provided session selection remains disabled. Setup checks routing metadata without reading private history. No canonical main conversation record existed before setup: the first verified hook created it. Reusing the existing main agent/workspace does not mean earlier chats were imported.

Make the receiving agent an explicit saved connection setting. Newly entered manual OpenClaw setup defaults to `main`; imported `liveabit.openclaw.connection.v1` setup must declare `agent_id`. The mapped `/hooks/liveabit` route requires `main`, matching the server-owned mapping. The legacy `/hooks/agent` route still supports explicit lowercase slugs matching `[a-z0-9][a-z0-9_-]{0,63}` and isolated runs, including earlier `liveabit` setups. Agent selection is effective only for those exact OpenClaw paths; event content cannot choose routing or a session.

Construct the webhook wrapper using the saved agent, then persist and retry the same bytes and event identity. Treat changing the agent like changing the endpoint or key: require explicit Start and confirmation before clearing unexpired pending activity. Preserve same-agent reconnects. Migrate earlier fixed-agent settings as `liveabit` so an upgrade cannot silently redirect queued activity to `main`.

The setup helper defaults `-AgentId` to `main`, installs the liveabit Skill in that existing agent's workspace and adds the selected agent to the hook allowlist while retaining earlier entries, including `liveabit`. If main explicitly limits available skills, add liveabit without replacing its prior list. Preserve `main`'s `AGENTS.md`, model, ordinary tool policy, heartbeat, other skills and unrelated configuration. Do not apply dedicated-agent restrictions to `main`. HTTP success remains run admission, not completed interpretation or user notification.

Goals, memories and conversation content remain in OpenClaw. Neither Android nor setup reads or copies them into the provider. The mapping creates or reuses the configured main conversation. Main output was observed for the synthetic event, preserving coverage and estimate uncertainty; access to earlier chats or private goals is not inferred. Untrusted activity cannot select a conversation or widen authority.

The native UI identifies the selected agent and derives Wi-Fi/USB instructions from the actual endpoint/port. Exact 0.5.0 APK bytes passed 37 Android 15/API 35 checks, including main admission; separate completed main output and additional emulator-to-host-LAN admission were verified. Main's configuration entry and AGENTS remained unchanged during that setup. See the [main-agent review](../review/openclaw-main-agent-2026-10-11.md). The `/events` receiver and legacy dedicated setup remain supported. Physical-phone delivery was not established. No intermediary, new account or JavaScript sender is introduced. Task IDs and formal M2/M3 scopes remain unchanged.

Subsequent 2026-10-11 development: WhatsApp is linked/connected, and 0.6.0 clarifies ordinary local responses versus separate selective-delivery policy. Model/thinking changes remain the user's choice; activity/channel setup preserves them. Sol 6.1 completed a separate operator run, with medium verified as inherited configuration. The explicit WhatsApp own-chat check received a provider message ID and preserved agent/model settings; phone receipt and notification for the checks are user-confirmed; selective coaching remains unproved. Editable quiet hours/cooldown are best-effort agent instructions; missing goals do not justify an unsolicited nudge. Preserve the recorded 0.5.0 evidence without transferring its passes to new bytes.
