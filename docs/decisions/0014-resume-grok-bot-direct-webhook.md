# ADR-0014: Resume the Grok Bot direct webhook integration

Date: **2026-10-08**. Status: **accepted by the user's explicit instruction to continue development for Grok Bot using the retained implementation**.

## Decision

The first integration target returns to **Grok Bot on the lowest eligible plan**, prioritizing its native direct routine webhook under [ADR-0011](0011-grok-bot-first-integration.md) and [ADR-0012](0012-grok-bot-direct-webhook-priority.md). This supersedes the active Meta Muse priority in [ADR-0013](0013-meta-muse-first-integration.md). The user has clarified that no Grok account exists yet and wants eligibility established before subscribing; the exact subscription product is not chosen. The target remains a genuine supported personal Bot, rather than an API-built replacement agent. Preserve the Muse research, completed bounded account assessment, local setup foundation, tests and evidence without relabeling them as Grok behavior. Preserve ChatGPT dots/MCP research, frozen Grok packets and Android evidence as well.

The [Grok webhook research](../research/grok-bot-webhook-feasibility-2026-10-08.md) documents a provider-issued POST URL, bearer authorization, JSON input and HTTP 200 acceptance/run-start report. The [current plan/webhook refresh](../research/grok-bot-plan-and-webhook-refresh-2026-10-08.md) distinguishes documented Bot access from actual account entitlement: [plans](https://cursor.com/help/grok-bot/plans) include Cursor Pro and linked individual SuperGrok, exclude SuperGrok Lite, and describe a seven-day usage-credit trial without automatic paid conversion. [Pricing](https://cursor.com/pricing) lists Cursor Pro at $20/month before tax. [Routines](https://cursor.com/help/grok-bot/routines) documents webhooks without a stated higher-tier restriction; availability on the lowest eligible Bot plan is a supported inference from those sources, not an observed account result or an explicit trial-webhook guarantee. These facts justify isolated development, without recommending a purchase as proof. Exact destination ownership, native credential lifetime/revocation, deterministic admission and delivery to the intended Bot remain unverified. No endpoint pattern, credential restriction or idempotency guarantee is inferred. Custom MCP Events remains separate and unverified; this decision does not pass AC-28.

## Immediate development

Reuse the retained synthetic-only single-attempt probe and develop [protected local Grok setup](../integration-drafts/grok-bot-local-setup.md). Capture exact setup details through bounded non-echoing local input, hold them briefly in RAM, avoid command-line/environment/config credentials and persistence, clear them on cancellation/expiry/attempt completion, and produce redacted outcomes. No live Grok account or credential is used in this resumption run. An owned final TLS mock may test the local path with synthetic data; it terminates that test and does not forward it to an agent.

A later real synthetic attempt requires an eligible personal account's supported routine interface, exact provider-owned destination and recipient, protected local setup, and an explicit single-attempt decision. Any trial inspection is conditional on the account actually exposing that feature; no trial webhook entitlement is promised. No automatic retry is introduced: an uncertain submission stops for reconciliation. A received HTTP 200 remains native transport/run-start evidence only, never an OAP valid-consumption receipt, observed evaluation or notification. Short local setup deadlines do not establish provider-enforced credential expiry or revocation.

The agreed `DirectAdapter`, publisher, OAP schemas and selectable profiles remain unchanged. Review native receipt/auth/capability differences and receiver admission/ledger before enabling any production native profile or Android sender. [AC-22/23/24/29](../../specs/acceptance-criteria.md), actual M2 and measured M3 remain unproven. The [resumption review](../review/grok-bot-resumption-2026-10-08.md) records this run's actual implementation and checks separately from retained evidence.

## Continuing constraints

Activity must travel directly from the producing device to the chosen agent's existing infrastructure. No project server, free-tier relay, proxy, broker, tunnel, mailbox, required desktop forwarder, user-operated bridge or paid API replacement agent is introduced. No purchase, subscription upgrade or on-demand spending is authorized.

The collector acceptance under ADR-0010 remains; further precise-duration/complete-coverage proof and Linux portability stay deferred. Unknown coverage stays unknown. Android inspector 0.2.4 and its tested APKs remain local-only and unchanged; every changed phone-trial APK still requires exact-byte emulator validation first. Keep all 33 requirement IDs and 29 acceptance IDs and their meanings stable. This changes the target and build order, not OAP 0.1.0 or milestone completion.
